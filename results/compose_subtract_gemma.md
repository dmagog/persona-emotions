# Системное вычитание X−sadness (Phase 4.1b) — gemma-2-2b, судья n=56 + CI

Обобщаем `anger−sadness` на все «протекающие» эмоции: для X ∈ {anger, disgust,
fear, guilt, shame} стирим `X − sadness` и проверяем, гасит ли вычитание
«аттрактор sadness» системно, сохраняя целевую X. `emotion/steer_compose.py`
(specs) → `judge_specificity` → bootstrap CI.

| X | снижение sadness (X → X−sadness) [95% CI] | целевая X в X−sadness vs baseline [95% CI] |
|---|------------------------------------------:|-------------------------------------------:|
| anger   | +39 [+27, +51] | +18 [+8, +29] |
| disgust | +29 [+17, +41] | +11 [+2, +20] |
| fear    | +33 [+21, +45] | +20 [+7, +32] |
| guilt   | +41 [+31, +50] | +3 [−9, +15] |
| shame   | +34 [+25, +44] | +34 [+21, +47] |

(Абсолюты: sadness-протечка X→X−sadness — anger +32→−9, disgust +33→+2,
fear +23→−10, guilt +42→+2, shame +47→+11.)

## Вывод

- **Вычитание системно убирает «аттрактор sadness»**: снижение значимо у всех 5
  эмоций (CI без 0).
- **Целевая эмоция сохраняется значимо у 4/5** (anger, disgust, fear, shame).
- **Исключение — guilt:** вычитание sadness гасит и саму вину (+3 [−9,+15], не
  значимо). guilt и sadness слишком слиты в этой модели (согласуется с тем, что в
  судейской матрице guilt~shame~sadness — один кластер).

То есть векторная арифметика даёт системный, статистически значимый инструмент
подавления off-target эмоции — то, чего простой промптинг не делает. Граница:
для очень близких эмоций (guilt↔sadness) вычитание не разделяет их чисто.
