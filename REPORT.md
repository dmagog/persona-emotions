# Emotion steering vectors in LLMs — interim report

Научная практика, 2-й семестр. Перенос метода persona/activation-vectors
(контрастные direction-векторы в пространстве активаций) с черт личности на
**эмоции**. Базовый код — PERSONA (xcfcode), метод — Persona Vectors
(arXiv 2507.21509). Командный датасет — Uliana Kliuchnikova.

## Задача и подход

Можно ли управлять **конкретной эмоцией** в генерации LLM, добавляя в residual
stream направление, извлечённое из контрастных пар «эмоциональный vs нейтральный
ответ»? И — насколько такое управление **специфично** (целевая эмоция vs прочие)?

Пайплайн: датасет (7 эмоций ISEAR) → независимое **измерение** эмоции (классификатор
+ LLM-судья) → извлечение **векторов** → **стиринг** → анализ **специфичности** →
первый шаг **расщепления**.

## Данные

7 эмоций ISEAR (anger, disgust, fear, guilt, joy, sadness, shame). На каждую —
~50–60 сценариев (held-out split отдельно). Для каждой пары инструкций
генерируются ответы Qwen2.5-3B-Instruct: `pos` (эмоциональный) и `neg`
(нейтральный) — контрастные пары.

## 1. Измерение эмоции (мерило)

Два независимых измерителя текста:

- **Классификатор-энкодер** `text→вектор`: `SamLowe/roberta-base-go_emotions`
  (GoEmotions, 28 меток) с агрегацией в 7 ISEAR. Метрика — **AUC** (разделимость
  pos vs neg, порого-независимая).
- **Pairwise LLM-судья** (`meta-llama/llama-3.3-70b-instruct` через OpenRouter):
  прямое сравнение pos vs neg ответа, 0–100 (50 = равно). Это согласованный с
  командой редизайн вместо одиночной шкалы.

**Энкодер (AUC по эмоциям):** disgust 0.82, anger 0.78, shame 0.69, fear 0.70,
sadness 0.64, joy 0.62, guilt 0.62; mean AUC 0.697. Все > 0.5 — энкодер разделяет
pos/neg по всем эмоциям. *(`results/encoder_scoring_qwen2.5-3b.md`)*

**Судья + кросс-проверка:** mean скоры 66.5–77.4, **832/920 пар** проходят порог 60.
Оба измерителя согласны по 6 из 7 эмоций. **guilt** — судья видит сильный контраст
(74.2), а энкодер слабый (AUC 0.62): это **ограничение энкодера** (GoEmotions
`remorse` плохо ловит вину), не датасета. *(`results/judge_vs_encoder_qwen2.5-3b.md`)*

## 2. Извлечение векторов

Для 832 judge-отфильтрованных пар: residual-stream активации Qwen2.5-3B,
`mean(pos) − mean(neg)` по слоям → 7 эмоц-векторов `[37, 2048]` (как в PERSONA,
формат совместим со стирингом). Прогон на домашнем RTX 2070.

**Находка:** попарные косинусы между эмоц-векторами **0.58–0.86** (все
положительны) — вектора НЕ ортогональны, доминирует общая компонента
«эмоционально vs нейтрально»; joy обособлен по валентности.
*(`results/emotion_vectors_qwen2.5-3b.md`)*

## 3. Стиринг работает

Добавление anger-вектора в `model.layers[14]` на нейтральных held-out промптах:
anger-скор **0.033 → 0.226 → 0.465** (coeff 0/4/8), монотонно; при coeff 8 — выше,
чем у инструктированных pos-ответов (0.362). Генерация связная и по теме.
*(`results/steering_anger_qwen2.5-3b.md`)*

## 4. Специфичность (ключевой результат)

Матрица 7×7 (стиринг к строке → Δ измеряемой эмоции vs baseline, layer 14, coeff 8):

- **Специфичные** (диагональ — максимум): **joy** (+0.46), **sadness** (+0.33),
  **fear** (+0.15).
- **Протекающие**: anger (+0.16, но sadness +0.23), disgust/guilt/shame — целевая
  почти не растёт, всё тянет вверх **sadness**.
- **«Аттрактор sadness»**: почти любой стиринг поднимает грусть — это проявление
  общей аффект-компоненты (см. косинусы). Вывод: **сырой стиринг ≈ общий аффект**,
  а не конкретная эмоция. *(`results/steer_specificity_qwen2.5-3b.md`)*

## 5. Расщепление (E0): вычитание общей компоненты

Вычли средний по 7 вектор (ренорм к исходной длине), повторили матрицу:

- **Аттрактор sadness убран**: протечка в sadness при стиринге к не-sadness
  эмоциям **+0.12 → −0.03**.
- **joy стал чище и сильнее** (+0.46 → +0.71); fear остался специфичным.
- **Но переусердствует**: **sadness схлопывается** (+0.33 → +0.02) — общий вектор и
  был по сути направлением sadness; часть эмоций сменили протечку (anger→guilt,
  disgust→anger). *(`results/steer_specificity_centered_qwen2.5-3b.md`)*

Mean-subtraction — грубый инструмент: убирает доминирующую ось, но не изолирует
каждую эмоцию. → мотивация для **SAE** (разреженный разбор, «минимальный эмоц-вектор»).

## 6. Расщепление через SAE (E1)

Перенесли векторы на **gemma-2-2b** (есть готовые SAE GemmaScope): эмоц-векторы
Gemma так же скоррелированы (косинусы 0.45–0.83) — **запутанность не специфична
для модели**. Затем спроецировали эмоц-направления на энкодер GemmaScope SAE
(`layer_12/width_16k`) и взяли топ-фичи.

- Наивная проекция: топ-фичи **почти идентичны** у всех эмоций, mean Jaccard **0.91**.
- После центрирования (вычесть общую компоненту, потом проекция): **0.84** — почти
  не помогло.

Вывод: **проекция difference-направления на SAE не изолирует эмоция-специфичные
фичи** — несколько доминирующих фич забирают проекцию у всех. Запутанность
устойчива по всем срезам: косинусы → специфичность → центрирование → SAE-проекция.
*(`results/gemma_sae_layer12.md`)*

## 7. Минимальный эмоц-вектор: контрастные активации SAE (E1c) — РАБОТАЕТ

Правильный метод: прогнать реальные pos/neg ответы через Gemma+SAE, ранжировать
фичи по **mean(pos)−mean(neg)** активаций (контраст гасит общий фон). Результат —
эмоции занимают **разные** фичи:

| метод | mean off-diag Jaccard |
|-------|----------------------:|
| проекция направления, наивная | 0.91 |
| проекция, центрированная | 0.84 |
| **контрастные активации** | **0.25** (min 0.08) |

Есть общие фичи (общий аффект), но у каждой эмоции — свои (anger 8517/16003/14599,
guilt 1041/8567, fear 621, joy 6648). **Методологический урок:** узким местом был
не SAE, а способ — проекция направления проваливается, контраст активаций
расщепляет. Это и есть рабочий «минимальный эмоц-вектор». *(`results/sae_contrastive_layer12.md`)*

## 8. Стиринг через SAE-фичи — замыкание цикла

Декодировали отобранные эмоц-фичи обратно в residual (Σ Δ·W_dec[f]) и стирили
ими gemma-2-2b, рядом с сырым вектором (матрица специфичности, layer 12, coeff 8):

| | mean диагональ | target=argmax | **протечка в sadness** |
|---|---:|---:|---:|
| сырой вектор | +0.20 | 3/7 | **+0.10** |
| SAE-фичи | +0.16 | 3/7 | **+0.05** |

**Feature-стиринг вдвое срезает «аттрактор sadness»** (anger→sadness +0.25→+0.01,
disgust→sadness +0.19→+0.04). Расщепление переносится в управление: разреженный
вектор тянет в общий негатив меньше сырого. Цена — чуть слабее целевой эффект, и
часть протечки перераспределяется (anger→fear). *(`results/steer_sae_feature_gemma.md`)*

## Выводы

1. Контрастные эмоц-векторы переносятся с черт на эмоции: стиринг **работает** и
   даёт связную генерацию.
2. Но «сырой» стиринг управляет **общим аффектом**, а не конкретной эмоцией —
   доказано матрицей специфичности и косинусами.
3. Простое центрирование убирает доминирующий аттрактор (joy/fear чище), но
   over-корректирует → нужен умный разбор (SAE).
4. Запутанность **устойчива** (переносится на Gemma, переживает SAE-проекцию), но
   **снимается контрастным разбором активаций SAE**: эмоции занимают разные
   разреженные фичи (Jaccard 0.25 vs 0.84–0.91 у проекции). Узкое место — метод, не
   SAE. Это рабочий «минимальный эмоц-вектор».
5. **Этим вектором можно управлять чище:** стиринг через SAE-фичи вдвое срезает
   протечку в sadness vs сырой вектор (+0.10 → +0.05). Цикл замкнут — нашли
   минимальный вектор и им управляем.

## Ограничения

- Энкодер слеп к guilt и почти не меряет disgust → для них честнее судья (учтено).
- Один целевой LLM (Qwen2.5-3B), один слой/2 коэффициента в специфичности.
- Стиринг `positions=all`, без подбора оптимального слоя на эмоцию.

## Дальше

- Усилить feature-стиринг: подбор слоя/коэффициента на эмоцию, top-k фич; добиться
  чтобы target=argmax для большего числа эмоций.
- Мерить guilt/disgust **судьёй** (энкодер их не видит) — честная оценка протечки.
- Больше моделей/слоёв; согласовать рамку новизны и деление с Уляной.
